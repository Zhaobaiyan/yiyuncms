## 二、目录逐项说明

### 1. app/ 应用目录（全部业务代码）

```
app\
├── middleware.php          # 全局中间件注册（顺序：LangRouter → AdminAuth）
├── BaseController.php      # 基础控制器（各应用控制器继承）
├── common.php              # 全局公共函数（多语言/配置/URL/设备/栏目跳转/分页）
├── service.php             # 服务注册（注册 LangAppService，动态生成语言 app_map）
├── admin\                  # 后台应用（controller + view）
├── index\                  # 前台应用（controller）
└── common\                 # 公共层（middleware / model / service / taglib）
```

#### 1.1 app/middleware.php —— 全局中间件
顺序重要：
1. `LangRouter`：前台语言解析（从 URL 首段识别 `/en/...`，注入 `_cms_lang`；后台路径跳过）
2. `AdminAuth`：后台鉴权（未登录访问后台 302 到登录页）

> TP6/TP8 全局中间件加载的是 `app/middleware.php`，不是 `config/middleware.php`。

#### 1.2 app/common.php —— 全局公共函数（二次开发最常用）
| 函数 | 说明 |
|---|---|
| `lang_codes()` | 已启用语言代码列表（如 `['cn','en','ru']`，读 yy_lang 表并缓存） |
| `default_lang()` | **默认语言（=主语言）**：优先 `is_default=1` 的已启用语言，否则排序第一个；静态页主语言规则以此为准 |
| `lang_code()` | 当前生效语言（后台读 session，前台读中间件注入） |
| `lang_set($code)` | 注入当前语言（`withMiddleware` 通道） |
| `lang_tpl_dir($code)` | 语言对应的**前台模板文件夹名**（读 `yy_lang.tpl_dir`，未设置回退语言代码） |
| `lang_is_default()` | 当前是否为默认语言（主语言）；**v3.18 路径站点下按站点 default_lang 判断** |
| `site_match()` | **站点匹配（v3.18）**：路径模式优先（URL 首段命中 `mode=path & status=1` 的站点 alias → 返回该站点），域名模式兜底（Host 精确/通配匹配） |
| `site_path_prefix()` | **站点前缀（v3.18）**：命中路径站点返回 `/{alias}/`，否则空串 |
| `lang_codes()` | 已启用语言列表；**v3.18 路径站点下按站点 langs 白名单 ∩ 全局返回**（缓存 `yy_site_langs`/`yy_lang_codes`） |
| `copy_dir($src,$dst)` | **递归复制目录（v3.18）**：站群/语言模板复制用（含子目录、空目录、防同级复制） |
| `lang_clone_tables($code,$srcLang,$withData)` | **克隆整套语言数据表（v3.18）**：枚举 `yy_{srcLang}_*` 全部表逐表 `CREATE TABLE IF NOT EXISTS ... LIKE`；`withData=true` 整表 `INSERT SELECT`，false 仅克隆 `_setting` 与 `_message_board` |
| `is_mobile()` | 判断当前 UA 是否移动设备 |
| `get_config($name,$default)` / `set_config()` | 读/写全局配置（yy_config，如 `wap.open`、`base.static_mode`、`content.pagesize`、`qiniu.*`） |
| `get_setting($name,$default)` / `set_setting()` | 读/写当前语言站点设置（yy_{lang}_setting） |
| `content_pagesize()` | 前台列表每页条数（后台可设，默认 10） |
| `site_url($controller,$action,$params)` | 生成带语言前缀的前台链接（主语言无前缀） |
| `url_cat($category)` | 栏目链接（静态优先；external/redirect 返回跳转目标；列表链接补尾斜杠） |
| `category_path($cat)` | 栏目静态路径（按 `base.static_url_mode` 生成：精准拼祖先 / 精简仅本栏目） |
| `sync_pretty_firewall($lang)` | 自动重写 `public/nginx.htaccess` / `.htaccess`（主语言代码、隐藏前缀） |
| `redirect_target_url($category,$depth)` | 解析跳转目标：`@栏目ID` / `@栏目ename` / `http(s)://` / `/` 路径，深度上限 5 防循环 |
| `url_content($content,$category)` | 内容详情链接（静态优先） |
| `url_home()` / `url_lang($code)` | 首页链接 / 语言切换链接 |
| `attach_download_rewrite($html)` | **附件下载链接重写**：把内容 HTML 中 `/upload/` 的非图片附件 `<a>` 重写为 `/download/index?file=…&name=链接文字`（下载按链接文字 + 原后缀命名）；图片链接保持原样。正文/描述/单页/自定义块/内容标签输出统一接入 |
| `content_people($authorUid,$auditUid)` | **发稿人/审核人信息（投稿审核）**：按管理员 ID 查 `yy_admin.nickname`，返回 `['author_name'=>, 'audit_name'=>]`；前台模板经 `{$content.author_name}` / `{$content.audit_name}` 调用 |

## 三、多语言 / 静态化 / 手机版 / 搜索 实现要点（二次开发必读）

### 1. 多语言如何工作
- **URL 规则（静态页规则，v3.0 新）**：
  - **主语言（默认语言，如 cn）**：首页 `index.html` 在站点**根目录**；栏目/内容静态页也在**根目录**（`news/`、`about.html`），URL **无语言前缀**（`xxxx.com/news`）。
  - **其他语言（如 en）**：首页与栏目/内容都放 **`en/` 文件夹**（`en/index.html`、`en/news/`），URL **带前缀**（`xxxx.com/en/news`）。
  - **主语言 = 默认语言**：由「语言版本 → 默认语言 is_default」控制，无需单独开关；改默认语言后重新生成静态页即按新主语言规则落盘。
- **动态语言路由**：`LangAppService` boot 阶段按 `yy_lang.is_open=1` 动态生成 `app.app_map`（缓存 `yy_lang_appmap`）。新增/停用语言无需改配置。
- **数据表**：模型继承 `LangModel`，表名 = `yy_{当前语言}_{实体}`。新增语言后台自动克隆默认语言**全部数据表**（动态枚举 `yy_{源语言}_*`）+ 复制默认 `_setting` 与留言板（`lang_clone_tables()`）。
- **语言注入**：`LangRouter` 解析 URL 首段 → `lang_set($code)`（`withMiddleware`）→ `lang_code()` 读取。
- **模板目录**：`lang_tpl_dir($code)` 读 `yy_lang.tpl_dir` 确定 `template/{tpl_dir}`（及 `/wap`）。**v3.18 语言列表新增「复制模板」按钮**：从源语言/站群站点复制整个 `template/{源}` → `template/{本语言}`（`copy_dir()` 递归复制）。
- **URL 生成**：一律用 `site_url()`/`url_cat()`/`url_content()`，主语言自动省略前缀。
- **后台录入**：顶栏语言切换 → session 记录当前语言 → 后台所有模型按当前语言读写。
- **跨语言复制**：内容列表顶部「跨语言复制」（勾选内容 → 选目标语言并加载其栏目树 → 选目标栏目 → 批量复制，`Content::batchCopyLang`，原内容保留、views 清零）；栏目列表顶部「跨语言复制」（勾选栏目 → 选目标语言 / 放置位置：顶级或某一级/二级下 → 整棵子树连同各级内容一起复制并保持层级，`Category::batchCopyLang`+`exportTree`/`rebuildTree`，父子同时选中只复制最顶层）。复制后到目标语言翻译。

### 2A. 站群系统（v3.18：路径模式 + 域名模式）
- **开关**：`site.multi` 存 `yy_config`（系统设置 → 网站设置 → 站群设置(全局)）。
- **站点表 `yy_site`**：`id/name/domain/alias/mode/default_lang/langs/status/sort/remark/create_time`；`mode=path`（路径别名模式，推荐）或 `domain`（域名绑定模式）。
- **路径模式机制**：URL 首段命中 `mode=path & status=1` 站点的 `alias` → `LangRouter` 注入 `_cms_site` → `site_match()` 返回该站点 → `default_lang()/lang_codes()` 按站点 `langs` 白名单 → 模板目录 `lang_tpl_dir()=alias` → **无需绑定二级域名**，`/{别名}/` 即站点入口。
- **站点创建（Site::save）**：路径模式新建时自动 ① 注册语言（code=alias，tpl_dir=alias，`Lang::create`）② 克隆整套数据库（`lang_clone_tables(alias, 源, withData)`）③ 复制模板目录（`copy_dir(template/源, template/alias)`）；删除站点时自动停用同名语言（数据表保留）。
- **站点模板复制**：站群列表行内「复制模板」/语言列表行内「复制模板」→ `copyTpl()`（POST src 源语言代码 → copy_dir）。
- **URL 前缀**：`site_path_prefix()` 命中路径站点返回 `/{alias}/`；`url_cat/url_content/url_home/url_homepage/url_lang` 全部叠加前缀。
- **静态生成（站点）**：`StaticPage::pubRoot/relPath` 对路径站点**始终** `public/{alias}/`（首页 `public/{alias}/index.html`、栏目 `public/{alias}/pro/index.html`），链接固定带 `/{alias}/` 前缀，与主站/其他站点静态完全隔离；`buildLang()` 开头按语言自动注入站点上下文。**注意**：路径站点不会被误判为全局主语言而写到 public/ 根（已修复）。
- **语言扩展**：路径站点编辑页勾选其他语言（cn/en 等）后，站内出现对应语言切换（`/{alias}/en/...`），数据走 `yy_{alias}_en_*` 独立表。

#### 2B. 站群推送与分站管理员（v3.20）
- **概念**：站点=独立语言代码（主站='main' 即全局默认语言，分站=站点别名）；跨站推送=跨语言复制 + 推送状态机；采纳/通过=`copyContent` 在目标语言表生成内容副本并回填 `target_content_id`。
- **推送表 `yy_push`（全局共享）**：`from_site/to_site/from_lang/from_catid/from_content_id/to_lang/to_catid/title/status(0待处理/1已采纳发布/2已拒绝/3已撤回)/target_content_id/creator_uid/creator_name/audit_uid/audit_name/remark/create_time/audit_time`。
- **发起**：内容管理 → 勾选内容 → 「推送到站点」（选择目标站点 → 目标栏目）。分站→主站提交后提示「等待主站管理员审核」；主站→分站由分站管理员「采纳/通过」后发布。
- **处理（PushSite 控制器）**：采纳/通过=复制内容到目标语言（可选改目标栏目，静态模式自动刷新目标内容页）；拒绝=必填原因；撤回=仅发起方可撤待处理记录。「待我处理」按当前站点 + 非 needAudit 角色过滤，「我发起的」按 from_site=当前站点。
- **分站管理员（site_scope）**：`yy_admin.site_scope` 存 JSON 语言/站点代码数组（空=全部）；非超级管理员且非空时——后台语言切换列表只显示其可管理站点/语言、`admin_sites` 同步过滤，实现「分站投稿员只能进分站后台 + 只能管理分站栏目内容」。角色权限（投稿员/审核员等）沿用 `yy_admin_role`，分站管理员同样可配需要审核（need_audit）。
- **菜单**：扩展功能 → 推送管理（`admin/push_site/index`，避开已占用路径 `admin/push/index` 收录推送）。
- **已实测闭环**：主站→分站采纳（分站内容表新增记录）、分站→主站审核通过（主站内容表新增记录）、拒绝（填原因）、撤回（发起方）全部浏览器验证通过。

### 2. 静态页生成（v3.2 规则 + v3.7.1 模板选择修复）
> v3.7.1：静态生成与前台控制器**使用同一模板选择规则**——首页优先 `index_index.html`、列表页用栏目 `template`（`list_xxx`）、单页/详情页用栏目 `content_template`（`show_xxx`）；云优转换模板自带完整 `<head>`，静态页与动态页样式完全一致。缺省时回退 `index/list/show`。
- `StaticPage::pubRoot($lang,$type)`：主语言 home→根、page→`{lang}/`（主语言文件夹）；其他语言全部→`{lang}/`。
- **主语言**：首页 `index.html` 在站点根目录；栏目/内容放**主语言文件夹**（`cn/news/`、`cn/about.html`、`cn/news/12.html`），`static_path` 无前缀 → **URL 无前缀**（浏览器链接不体现 `cn`），前缀由伪静态隐藏。
- **其他语言**：`en/index.html`、`en/news/`、`en/about.html`，`static_path` 带 `en/` 前缀 → URL 带 `/en/` 前缀。
- **伪静态隐藏前缀（自动生成）**：`sync_pretty_firewall()` 在「设为默认语言」「静态页生成」时自动重写 `public/nginx.htaccess` 与 `public/.htaccess`，把主语言代码写入规则：Nginx 用 `rewrite`（无斜杠一级栏目→`/{lang}/$1/index.html`，不泄露前缀）+ `try_files $uri $uri/ /{lang}$uri /{lang}$uri/ /index.php?s=$uri&$args`；Apache 用主语言映射 RewriteRule。改默认语言无需手工改规则。
- **栏目静态URL规则（base.static_url_mode）**：`category_path()` 按开关生成层级路径——**精准(accurate，默认)**拼接全部祖先别名（`pro/pro1/1/16.html`，单页也带父层级如 `aboutus/about.html`）；**精简(compact)**只留最后栏目（`pro1/1/16.html`）。
- **`url_cat()`**：静态优先，输出 `'/' . static_path`；**列表栏目链接统一补尾斜杠**（`/news/`、`/pro/pro1/`），避免伪静态对目录 301 时暴露主语言前缀。
- 后台「静态页生成」：当前语言全站 / 指定语言全站 / 全部语言全站。
- 开启 `base.static_mode` 后，发布/编辑内容自动刷新对应语言静态页。
- `render()` 已补齐 `is_wap=false/lang_code/cur_url` 三变量（静态生成固定 PC 版）；`write()` 自动 `mkdir`；单页 content 数组补全 `id/catid/author/source/flag/views/description/thumb/create_time`；`{cms:prevnext}` 对无 id 内容容错。

## 七、富文本编辑器
- 全站统一 **UEditor**（云优同款，`public/static/admin/ueditor/`，21 按钮工具栏），服务端 `Ueditor.php`（`/admin/ueditor/index?action=config|uploadimage|listimage`）。
- 内容主编辑器高 400、描述(简易富文本)120、栏目内容 320、自定义块 320；`.edui-editor` z-index 已覆盖防遮挡。
- 「描述 desc」简易富文本放正文上方，前台 `{$content.desc|raw}`；栏目「描述」简易富文本、栏目「内容」富文本 `{$category.content|raw}`。
- **模板转义陷阱**：`config/view.php` 未设 `default_filter`，ThinkPHP 模板默认对 `{$var}` 输出做 htmlspecialchars 转义。因此所有 **UEditor 富文本回填容器**（`<script id="content|contentdesc|catcontent|catdesc" type="text/plain">`）输出必须加 `|raw`（如 `{$info.content|default=''|raw}`），否则 `<p>` 等标签在编辑器里会显示成文字 `&lt;p&gt;`。
- **附件/图片上传必需 `uploadType`**：云优版 UEditor 的附件/图片对话框在 `startUpload` 时用 `uploader.option('server', uploadUrl)` 覆盖上传地址；`initUploadType` 里只有 `uploadType == 'local'` 才走本地上传分支，否则取 `uploadQiniuUrl`（未配置=空）→ server 被清空 → 上传 POST 到对话框自身 `attachment.html` 返回 405。**`Ueditor::config()` 必须返回 `'uploadType' => 'local'`**（本地/php 上传场景）。
- **在线管理/在线附件空白**：云优版 UEditor 的多图对话框「在线管理」用 `getOpt('imageManagerActionName')`、附件对话框「在线附件」用 `getOpt('fileManagerActionName')` 拼请求地址；本版 `ueditor.config.js` 未给默认值，若 `Ueditor::config()` 返回里没有这两个键，请求会变成 `?action=`（空）→ 后端返回「无效的 action」→ 列表空白。**`Ueditor::config()` 必须返回 `'imageManagerActionName' => 'listimage'`、`'fileManagerActionName' => 'listfile'`**（服务端 config 会被 `utils.extend(me.options, config)` 合并进编辑器 options）。
- **在线列表图片加载失败**：对话框渲染缩略图/附件时 `src = urlPrefix + list[i].url`（`image.js` 用 `imageManagerUrlPrefix`、`attachment.js` 用 `fileManagerUrlPrefix`），config 缺这两个键时 `getOpt` 返回 `undefined` → 图片 src 变成 `undefined/upload/…` 加载 404。**`Ueditor::config()` 必须返回 `'imageManagerUrlPrefix' => ''`、`'fileManagerUrlPrefix' => ''`**。
- **全屏失效/被导航遮挡无法退出**：云优版 UEditor 全屏走 JS 内联样式（`_updateFullScreen` 原写 `position:absolute;z-index:原zIndex+100`）；后台 `admin.css` 为防遮挡把 `.edui-default .edui-editor` 强制 `z-index:10!important`，会**压掉全屏内联 z-index** → 全屏层层级低于左侧导航(z-index 50)/顶栏(40)，导航不消失、工具栏退出按钮被顶栏盖住无法点击。修复：`_updateFullScreen` 改为 `position:fixed` + `z-index:9999!important`（内联 `!important` 优先于样式表 `!important`）。**模板实际加载的是 `ueditor.all.min.js`，必须改 min 版**（`ueditor.all.js` 非压缩版同步改保持一致）。**注意**：`public/static/admin/ueditor/` 静态资源仅部署目录 `D:\phpstudy_pro\WWW\newcms` 有副本，权威副本 `F:\豆包下载\CMS` 无该目录，改 ueditor 文件只需改部署端，无需同步 F；改后浏览器需强刷（Ctrl+F5）清除静态 JS 缓存。

### 附件下载（改名 + 原后缀）

## 十一、后台前端脚本加载顺序（关键根因）

## 十四、后台管理员角色权限
为不同管理员分类配置后台权限（如投稿员只可发布内容、留言查看只看留言、SEO优化管友情链接）。
- **角色表 `yy_admin_role`**（共享表）：`code`（标识唯一）、`name`、`rules`（**控制器白名单 JSON**，`"*"` 表示全部权限）、`cat_ids`（**栏目数据范围**，JSON 按语言分组 `{"cn":[1,2],"en":[]}`，某语言缺失/空数组 = 该语言不限制全部）、`board_ids`（**留言板数据范围**，同样按语言分组）、`remark`、`is_system`（内置角色不可删）、`status`、`sort`。
- **内置角色**：`super` 超级管理员（`*`，不可改）、`admin` 普通管理员（可配置）、`tougao` 投稿员（内容管理+上传）、`message` 留言查看（留言管理+留言板）、`seo` SEO优化（友情链接+系统设置）。内置角色不可删除；其余角色可自由增删改。
- **可勾选权限模块**（`AdminRole::$modules`）：内容管理/栏目管理/内容模型/留言板/留言管理/自定义块/广告位/模板管理/静态页生成/友情链接/管理员/系统设置/语言版本/图片上传/富文本上传。
- **数据范围（v3.3）**：角色编辑页在权限模块下提供「栏目范围」「留言板范围」复选，把权限收窄到具体对象；范围按后台当前语言分别保存（切语言可配不同范围）。`AdminBase` 提供 `roleScope/dataScopeCats/dataScopeBoards/canManageCat/canManageBoard/filterCategoryTree`：
  - **栏目范围**：勾选某栏目自动含其**全部后代**（`Category::getChildIds` 展开），空 = 全部。生效于 `Category`（index/add/edit/delete/sort/batchData/batchAdd/editField/copyLang/batchCopyLang 的树过滤与校验）与 `Content`（index 只查权限栏目内容；add/edit/delete/batch/batchCopy/batchMove/copyLang/batchCopyLang/editField 校验 catid / 所选内容 / 目标栏目）。
  - **留言板范围**：空 = 全部。生效于 `Board`（index 列表过滤；edit/fields/field_edit/field_delete/delete/code 校验 board_id）与 `Message`（index 列表与下拉过滤；reply/audit/delete 校验留言所属板子）。
  - **超级管理员**不受数据范围限制（方法直接返回 null = 全部）。
- **菜单过滤**：`AdminBase::initialize` 读会话 `admin_role` → `roleRules()` 查角色表 → `filterMenus()`/`canCtrl()` 只保留该角色有权限的菜单项；`super` 直通全部。
- **URL 拦截**：`AdminAuth` 中间件对已登录非超级管理员，按请求控制器比对角色白名单，越权访问页面重定向控制台、AJAX/POST 返回 403；`index/login/upload/ueditor` 总放行（发布内容需勾「内容管理」+「图片/文件上传」）。
- **管理员选角色**：`Admin.php` 编辑页「角色」下拉（读启用角色表），保存写 `yy_admin.role`；不能把当前登录的超级管理员降级、不能删除当前登录账号与 id=1。
- **登录会话**：`Login::login` 成功后写入 `admin_role` 会话；退出时清除。
- **升级**：老库执行 `database/upgrade_admin_role_scope.sql`（`yy_admin_role` 增加 `cat_ids` / `board_ids` 两列）；`install.sql` 建表已含两列。

## 十五、投稿审核机制（v3.5）与审核驳回闭环（v3.6）

**目标**：投稿员等角色发布内容默认进入**待审核**，需管理员/审核角色审核（通过/驳回）；后台可追溯发稿人、审核人、审核时间、第几次提交与历次原因；前台可调用显示。

### 1. 数据库变更
- `yy_{lang}_content` 新增三列（每语言内容表，install.sql 已含、老库用 `upgrade_audit.php` 升级）：
  - `author_uid` INT UNSIGNED 默认 0 —— **发稿人管理员 ID**
  - `audit_uid`  INT UNSIGNED 默认 0 —— **审核人管理员 ID**（管理员直接发布时 = 发稿人，同人）
  - `audit_time` INT UNSIGNED 默认 0 —— **审核时间**（时间戳）
- `yy_admin_role` 新增 `need_audit` TINYINT 默认 0 —— 1 = 该角色**发布内容需审核**。
- 内置角色默认：`super/admin/message/seo` 免审核，`tougao`（投稿员）需审核。
- **v3.6 追加**（每语言内容表）：`audit_status` TINYINT（0 正常 / 1 待审核 / 2 已驳回）、`submit_count` INT（提交次数，首次 1）、`reject_reason` TEXT（最新驳回原因，历史原因存日志表）。
- **v3.6 新增日志表** `yy_{lang}_content_audit_log`：`content_id/type(1提交/2驳回/3通过)/uid/note/create_time`，全程留痕，多次驳回追加不覆盖。

### 2. 判定入口
- `AdminRole::needAudit()`：读 `session('admin_role')`，空或 `super` 直接 false，否则查角色表 `need_audit==1`。

### 3. 内容侧规则（`Content.php`，统一入口 `resolveStatus($formStatus, $row)`，v3.6 返回 5 元：status/audit_uid/audit_time/audit_status/submit_count）
| 场景 | 需审核角色 | 免审核角色 |
|---|---|---|
| 新建（add） | 待审核 `status=0/audit_status=1`，`submit_count=1`，记日志 type=1（首次修改说明） | 默认直接发布 `status=1`，**发稿人即审核人**（audit_uid=当前管理员，audit_time=now），`audit_status=0`，记日志 type=3；选草稿则无审核记录 |
| 编辑（edit） | 保存即**重提**：`audit_status=1`、`submit_count+1`，记日志 type=1（含「修改说明」输入框内容） | 原待审核/已驳回→表单发布：审核通过（audit_status=0、记审核人/时间、日志 type=3）；原发布保持不变 |
| 行内切换状态（editField，0→1） | 拒绝（提示"该角色发布内容需审核，请由管理员或审核角色操作"） | 发布并记录审核人/时间 + 日志 type=3 |
| 批量设置（batch，status=1） | 拒绝 | 发布并批量记录审核人/时间 + 日志 type=3 |
| 同语言复制（batchCopy） | 副本进入待审核 | 副本保持源状态；源发布则记录审核人=操作者 |
| 跨语言复制（copyLang/batchCopyLang） | 副本进入待审核 | 副本保持源状态；源发布则记录审核人=操作者 |
- `collectPost()` 会 **unset `author_uid/audit_uid/audit_time/audit_status/submit_count/reject_reason/audit_note`**，杜绝表单注入伪造（修改说明由 add/edit 单独 `input('post.audit_note')` 读取）。
- 内容列表（`content/index.html`）新增「发稿人/审核人」列，显示管理员昵称（`Content::index` 查 `yy_admin` 建 `people` 字典）。

### 3.5 审核接口（v3.6，仅免审核角色可用）
- `audit()`（POST `id/act=pass|reject/reason`）：通过 → `status=1/audit_status=0`、记审核人/时间、日志 type=3、刷新静态详情；驳回 → `status=0/audit_status=2`、`reject_reason=原因`、日志 type=2、删静态详情 + 刷新栏目页（原因必填）。
- `auditLog($id)`（GET）：返回 `submit_count`、`reject_reason`、`status/audit_status` 与完整时间线 `logs`（type/操作人昵称/时间/note），供审核对话框渲染。
- 列表视图：状态列三态（待审核黄 / 已驳回红 / 发布草稿可切换），操作列仅 `canAudit && audit_status!=0` 时显示「审核」按钮，弹窗对话框 `openAudit()` 展示时间线并提供通过/驳回（追加原因不覆盖历史）。
- 编辑页（v3.6）：发布信息条显示审核状态/第几次提交/驳回原因；**免审核角色在待审核/已驳回状态下显示「审核操作」区**（原因输入框 + 审核通过/驳回按钮，直接调用 `audit()`）；需审核角色显示「修改说明」输入框（重新提交用）。
- **变化日志 type=4「下架/存草稿」**（v3.6 追加）：审核通过后的内容被改为草稿/下架（编辑保存、行内切换、批量下架）会记录一条 type=4 日志，信息条同步提示"当前为草稿/下架状态，变化见下方操作记录"。
- **操作记录时间线（编辑页）**：编辑页显示该内容全部审核日志（提交/驳回+原因/审核通过/下架存草稿，含操作人昵称与时间），与审核对话框时间线一致。

### 4. 静态页联动（下架/草稿安全）
- `StaticPage::remove($relPath)`：按 `static_path` 删除静态文件（防目录穿越）。
- 发布 → `refreshContent`（生成/刷新详情与栏目页）；**下架/草稿 → 删除该内容静态详情页 + 刷新栏目列表页**（防未登录者直接访问 .html 文件看到内容）。接入点：`edit`（编辑改状态）、`editField`（行内切换）、`batch`（批量下架/发布）。

### 5. 前台字段（模板调用）
- 详情页（动态 `Show.php`、静态 `StaticPage::content`、`{cms:content}` 标签 `TagService::content`）统一注入：
  - `{$content.author_name}` —— 发稿人昵称（空串则未填）
  - `{$content.audit_name}` —— 审核人昵称（空串则未审核/未填）
  - `{$content.author_uid}` / `{$content.audit_uid}` —— 原始管理员 ID
  - `{$content.audit_time}` —— 审核时间戳（模板用 `|date='Y-m-d H:i'` 格式化）
  - `{$content.audit_status}` —— 审核状态（0 正常 / 1 待审核 / 2 已驳回）
  - `{$content.submit_count}` —— 提交次数（第几次提交）
  - `{$content.reject_reason}` —— 最新驳回原因（空串则无）
- 单页（single）栏目渲染的 content 伪数组补齐上述字段（均为空/0）。
- 数据源：`content_people($authorUid, $auditUid)` 公共函数查 `yy_admin.nickname`（共享表，不随语言变化）。
